# ADR 0004：媒体任务由 Host 持有生命周期与工具契约

- 状态：已采纳
- 版本：v0.3.2
- 日期：2026-08-15

## 背景

旧实现把媒体工作台当作一个等待十分钟的 IPC：WebView 直接提交字符串参数，Host 临时启动 `grok --single`，结束后递归扫描 stdout 中所有字符串来猜测文件路径。由此产生了四个相互放大的问题：

1. UI 提供 `1080p`、`4K`、5 秒等当前 Grok Build 工具不接受的值，Host 没有自己的参数契约；
2. 纯文本视频要求调用已不再注册的 `video_gen`，功能入口存在但没有可达的成功路径；
3. 页面切换会失去运行状态，也没有可终止整个子进程树的任务句柄；
4. 模型正文、任意工具文本和结构化工具输出被同等对待，路径授权依赖启发式扩展名扫描。

关键问题不是媒体面板选项不准确，而是媒体能力没有后端权威：参数、任务、参考图、进程和产物分别由不同层临时决定。

## 决策

新增 `MediaService`，并让 Host 成为以下不变量的唯一表达位置：

- 只允许当前 Grok Build 实际注册的 `image_gen,image_to_video`；`--always-approve` 不得扩大到该闭集之外；
- 图片数量为 1–4；视频时长只允许 6/10 秒，分辨率只允许 480p/720p；前端通过 `media_generation_capabilities` 读取这些值，不维护第二份选项表；
- 纯文本视频由 Host 明确编排为 `image_gen` 首帧后接一次 `image_to_video`；参考图视频只允许一次 `image_to_video`；
- `start_media_generation` 立即返回任务快照，后续状态通过 `media-generation-changed` 投影；切换页面后用 `media_generation_status` 恢复；
- 任务快照同时写入 Host 持有的 `media-jobs.json`。写入使用 0600 临时文件和原子替换；现有文件为空、损坏、版本未知或违反上限时进入只读保护，不能被新任务静默覆盖；
- 启动时恢复最近 40 个任务；上次进程退出时仍为 queued/running/cancelling 的任务必须结算为带 `MEDIA_JOB_INTERRUPTED` 的 failed，不能推断为成功或自动重放；
- 恢复 journal 时重新校验本地产物仍位于该任务工作区或 `GROK_HOME/sessions`，远程产物仍满足 HTTPS 与域名策略；仅为当前存在且通过校验的确切文件恢复 asset 预览授权，journal 不能借持久化路径扩大文件访问；
- Host 最多同时执行 4 个媒体任务，且同一工作区、同一媒体类型只能有一个活动任务；限制随能力契约返回，避免 WebView 另存默认值；
- `cancel_media_generation` 终止 Grok Build 进程组（Unix）或 Job Object（Windows），而不是只让按钮恢复可点；
- stdout/stderr 始终被完整排空并限制内存保留量；超时、协议截断和读取失败均显式失败；
- 只解析 `streaming-json` 中与已知 toolCallId 绑定、状态为 completed 的 `rawOutput.path/uploaded_url`，不再扫描模型正文；
- 本地产物必须位于当前工作区或当前 `GROK_HOME/sessions`，然后只授权确切文件；远程产物继续受 HTTPS、凭据、元数据地址和媒体域名策略约束；
- 参考图保存到应用缓存并返回不透明 ID。WebView 不再向生成命令提交本地路径；引用释放后由 Host 删除，进程使用期间由租约阻止提前删除，启动时清理崩溃遗留；
- 生成、状态、取消、参考图保存和释放只接受主窗口调用；取消与释放还必须重新校验当前工作区归属，任务事件只投递给主窗口。

后台失败使用 `protocol` 或 `environment` 分类，并同时携带稳定 code、用户消息和下一步操作。用户输入、任务冲突和工作区归属使用 `operation`；journal、缓存和进程环境使用 `environment`。前端不再从中英文文案推断错误域。用户输入契约错误在启动前直接拒绝，不创建“注定失败”的任务。

## 结果

媒体工作台现在可以跨页面和应用重启恢复状态、真实停止任务，并且不会再把不受支持的 UI 选项交给模型猜测。结构化产物与普通文本的信任边界明确，Grok Build 输出在其真实会话目录中也能被识别，而不会因“不在项目目录”被静默丢弃。

任务 journal 只保存有界元数据和产物引用，不复制媒体文件本身。用户在外部删除产物后，历史任务仍会存在，但打开产物会明确失败；这是“任务事实”和“文件可用性”分离后的预期结果。
