# ADR-0001：会话回合由 session/prompt RPC 结果裁决

- 状态：Accepted
- 日期：2026-08-13

## Context

Grox 通过一个共享的官方 `grok agent stdio` 进程承载多个应用会话。ACP 还会发送 `turn_completed` 和 `_x.ai/session/prompt_complete` 等通知，但这些通知可能早于流式输出真正结束。共享进程退出或切换供应商时，连接状态、各会话回合和本地提示队列也会同时受到影响。

如果任何早到通知、当前查看页面或自动重连都能直接把会话改为 idle，就会出现跨会话串流、队列抢跑、停止按钮失真和“异常退出后看似成功”的问题。

## Decision

1. `session/prompt` RPC 的 resolve、reject 或用户取消是回合结束的唯一裁决；完成通知只更新用量等旁路信息。
2. 所有流、门禁、停止、错误和队列操作必须携带明确的会话 ID；当前查看会话不能作为协议路由依据。
3. ACP 进程连接状态与会话回合状态分开表达。自动重连成功不把被中断回合改写为成功，而是保留 failed 并暂停其队列。
4. v0.3.2 继续使用一个共享官方 CLI 进程，不在 Rust 与前端各建一套平行 FSM。前端 Bridge 提供协议事实，Store 持有唯一的产品状态；未来只有在官方 CLI 明确要求进程隔离时才引入进程池。

## Consequences

- 多会话仍可并行流式运行，同时供应商切换会等待所有活动回合结束。
- 停止、恢复、断连和失败成为用户可见的不同状态。
- 提示队列必须持久化，并在运行时事故后等待用户显式恢复，不能自动重发可能已经执行过的内容。
- 共享进程仍意味着进程级崩溃会影响多个会话；错误必须按受影响会话归属并保留诊断。
